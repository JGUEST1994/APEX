- Meta-labelling (H50): `ml/meta.py` `MetaLabeled` wraps any strategy (`<KEY>+META`; reference strategy ML-META-001 = Donchian breakout + meta-model). Tests: causality, filter-only, learns to drop the losing side of a no-skill primary in a drifting market and raises its Sharpe, warm-up modes.

- `apex.backtest` (Phase 5 core): bar-based event-driven engine (`engine.py`) that fills at the next bar's open (configurable latency, never same-bar), sizes by equity x leverage rounded to lot size, trades only on target changes, charges commission/spread/slippage/funding from the instrument `CostModel` with a stress multiplier; metrics (`metrics.py`): total return, CAGR, volatility, Sharpe, Sortino, max drawdown, Calmar, win rate, profit factor, expectancy, average win/loss, max consecutive losses, trades/year, exposure, % positive months, costs; reproducible experiments (`experiments.py`) recording data SHA-256, git commit, full params and config, and registering strategy versions with a code hash (refuses to reuse a version number after the strategy code changes). CLI `apex backtest`, `apex strategies`; API `/experiments` (all flagged simulated). Hand-calculated reference tests for fills, P&L, costs, flips, futures multipliers.
- Phase 5 validation (`backtest/validation.py`): rolling or anchored walk-forward optimisation (grid search in-sample, evaluation on the next unseen window, stitched out-of-sample returns, walk-forward efficiency, parameter stability), Probabilistic and Deflated Sharpe Ratio (trial count = grid size x folds), Probability of Backtest Overfitting via CSCV, Monte Carlo bootstrap of outcomes, parameter sensitivity, hold-out split. `run_validation` records a `walk_forward` experiment with all of it; CLI `apex validate`.
- Phase 6 tournament (`backtest/tournament.py`, `strategies/lifecycle.py`): runs walk-forward validation for each strategy x symbol, re-deflates the Sharpe ratio with the family-wide trial count (every walk-forward trial ever recorded for that strategy key), checks promotion gates (min OOS trades 100, family DSR >= 0.95, >= 60% profitable folds, max drawdown <= 25%, PBO <= 0.5), and scores on robustness (DSR, fold consistency, drawdown, PBO, parameter stability; raw return has no weight). Gate failures are explained in plain English with the technical name in brackets (e.g. "could be luck: confidence the edge is real 41%, needs 95% (deflated Sharpe)"); thresholds unchanged. Auto-promotion goes experimental -> backtesting -> validation only; `approved` needs a human actor. Every status change writes `strategy_status_changes` and an audit event. `--regime-filter` also enters `<KEY>+RF` variants that share the base strategy's trial family. CLI `apex tournament`, `apex leaderboard`; API `/leaderboard` (flagged simulated).
- Phase 8 regimes (`apex.regime`): causal efficiency-ratio trend regime (`trending`/`range`, matching `StrategyMeta.regimes`), trailing-percentile volatility regime, and a dependency-free Gaussian HMM fitted on a training window then run as a forward filter (never smoothed) on later data. Stability (switch rate, mean run) and an out-of-sample check (forward realised vol per HMM state). `RegimeFiltered` wraps any strategy as `<KEY>+RF` and zeroes positions outside its declared regimes; its version fingerprint covers the wrapped code. CLI `apex regimes`, `--regime-filter` on `backtest`/`validate`. Tests check the HMM recovers known regimes out of sample (>85% accuracy on synthetic switching data) and that every label is causal.

- Phase 9 slice 1 (reviewed and approved by Jake 2026-11-19): `apex.risk` is an independent package that imports only `apex.core` (enforced by a test). It holds `RiskLimits` (can only be tightened automatically) and `RiskService` (paper mode only; refuses research). Slice 2 (`execution/store.py`, Alembic 0004: `paper_accounts` incl. kill switch, `paper_orders`, `paper_fills`, `paper_positions`) commits each processed bar in one transaction. CLI `paper-create`, `paper-run` (cron-safe, processes only new stored bars), `paper-reset-kill`; all refuse unless `APEX_TRADING_MODE=paper`. Correlated-exposure cap: `risk/correlation.py` groups symbols whose absolute return correlation is >= 0.7 (single linkage, min 30 overlapping observations); `RiskService.check` refuses new risk that would put more than `max_cluster_exposure` (40% of equity, tighten-only) into one group, while reducing orders stay allowed. Paper-vs-backtest consistency (`execution/consistency.py`, CLI `paper-compare`, `GET /paper/accounts/{name}/consistency`, shown on the Practice trading tab) re-runs the backtester over exactly the bars an account processed and compares direction per bar, position changes and fill prices; >= 95% direction agreement and <= 1 bp fill gap count as consistent, and known causes (kill switch, losing-streak limit) are explained. Building it exposed two paper bugs, now fixed and tested: a reversal was sent as one order and, if the new side was refused (e.g. risk per trade on the combined size), the old position stayed open; now the close goes first as its own always-allowed reducing order. And every partial trim counted towards the losing streak; now one round trip counts once (open-trade P&L is rebuilt from the fill ledger on restart). Losing streak (Jake's decision 2026-11-19): reaching `max_consecutive_losses` now trips the kill switch, so the account flattens and waits for a named human reset, which also clears the streak (recorded in the audit log). ## Known limitations

- NYSE regular early closes (13:00 ET on 3 July and 24 December when Mon-Thu, and the day after Thanksgiving) are modelled, and so are one-off full closures since 2000 (`NYSE_SPECIAL_CLOSURES`: 9/11, Hurricane Sandy, presidential days of mourning up to Carter 2025-01-09); future one-offs must be added by hand. CME/FX holidays approximated (25 Dec, 1 Jan, CME Good Friday); other exchange holidays and early closes will show as gap warnings.
- Research search scans chunks in memory up to 20,000 chunks. Beyond that, on PostgreSQL, a GIN full-text index (migration 0006) picks the best 2,000 keyword candidates first and only those are re-scored, so a chunk with no keyword match is not found and BM25 statistics come from the candidates. SQLite always scans in memory. pgvector-based semantic candidates are not used yet.
- The default embedder is lexical (feature hashing). Install `sentence-transformers` with a local model for true semantic similarity.
- Scanned PDFs (no text layer) are rejected: OCR not supported yet.
- YouTube: APEX imports transcript files the operator obtained through an authorised route; it does not fetch from YouTube. An official-API fetcher (YouTube Data API captions for channels you own, or platform exports) is a later addition.
- API access control is one optional shared token (`APEX_API_TOKEN`; no user accounts). Without it, keep the API on localhost (the default, including Docker).
- Backtester does not yet model: margin calls, partial fills, intrabar stop/limit orders, market impact beyond bps slippage, futures roll. Positions open at the end are marked at the last close and counted as a trade (`closed_at_end`).
- Plain `apex backtest` Sharpe is raw; use `apex validate` for out-of-sample, trial-adjusted figures. The tournament uses family-wide trial counts; `apex validate` alone counts only its own grid.
- Session-close detection uses the calendars above, so intraday strategies inherit their approximations (CME/FX early closes are not known, and future one-off NYSE closures must be added by hand).
- Daily bars use 00:00 UTC of the session date as `ts`; providers with other conventions must be mapped.
